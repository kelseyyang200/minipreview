# 版本检测 / 强制刷新 / 更新日志组件

## 功能概述

静态页面（help.wshoto / GitHub Pages 等）有 CDN 缓存问题：部署新版本后用户拿到的可能还是旧 HTML。本组件用「版本号对比 + 强刷」解决，同时提供右上角版本徽章、更新日志弹层、一键刷新按钮。

## 组件结构（工具栏一级，无二级菜单）

```
toolbar 末尾（从左到右）：… 📤 分享批注 | 🔄 一键刷新 | 🔔 v1.3.x · 08/27
                                                  │            └ 点击展开 .vb-popover
                                                  │               （📜 更新日志 + 提示文案）
                                                  └ 点击即 hardRefresh()，直接刷新
```

「一键刷新」是工具栏一级按钮（1.3.1+），点击本身就是触发刷新，不藏在任何弹层里；🔔 徽章只负责展示版本与更新日志。

## 版本号体系

- `APP_VERSION`：当前构建版本（script 顶部，改动上线必更新）。
- `CHANGELOG`：更新日志数组，最新在首位；徽章文本取 `CHANGELOG[0]`。
- 远端检测：fetch 自己的 URL（`cache:'no-store'` + `_v=时间戳` 参数）拿真·最新 HTML，正则 `const\s+APP_VERSION\s*=\s*'([^']+)'` 提取远端版本号。

## 防无限刷新的四道防线（改这里必须读懂）

| # | 防线 | 实现 |
| --- | --- | --- |
| 1 | 会话级熔断 | `sessionStorage['mp:forceRefreshed']` 存在则 `initVersionGuard` 直接 return——同一会话**最多自动强刷一次** |
| 2 | 强刷必绕缓存 | `hardRefresh()` 用 `location.replace` 追加 `_fr=时间戳` 参数 → 新 URL 不命中缓存，必然拿到新版 |
| 3 | 失败不动作 | fetch 网络失败 / `!res.ok` / 正则解析不到版本号 → 一律不刷新 |
| 4 | 有差异才刷 | 只有远端版本号 ≠ 本地 `APP_VERSION` 才刷 |

最坏情况推演：CDN 忽略查询参数（罕见）→ 强刷后仍旧版 → 防线 1 熔断，绝不再刷。

## 其他细节

- `hardRefresh` 保留原 query（含分享链接 `?data=`）和 hash，只追加/覆盖 `_fr`。
- `_fr` 参数落地后残留在 URL 上无副作用（页面不读取；分享链接生成用全新 URL 不携带）。
- 一键刷新（手动）不设会话标记：刷新拿到新版后版本一致自然停止；若 CDN 怪异仍旧版，自动检测最多再补一次（共 2 次）后熔断。
- 徽章默认 z-index 60，位于批注面板上方，收起时只占一枚小徽章空间。

## 每次部署的固定动作

1. 改代码；
2. `APP_VERSION` 递增 + `CHANGELOG` 加一条；
3. `ws-quick-html-deploy` 的 `update-file` 部署（地址不变）；
4. 验证线上 `curl -s <url> | grep APP_VERSION` 与本地一致。
